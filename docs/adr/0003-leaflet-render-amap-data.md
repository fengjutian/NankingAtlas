# ADR-0003：地图栈改为「Leaflet 渲染 + 高德提供数据」

状态：**已接受（Accepted）**
日期：2026-10-10
决策者：仓库维护者（用户）
适用范围：`apps/web` 的地图渲染层、坐标换算、CSP 配置

## 1. 背景

代码当前**完全由高德 JS API 2.0 渲染**（`AMap.Map` / `AMap.Marker` / `AMap.Pixel`，
见 `MapCanvas.tsx`），Leaflet 已不在依赖里。而技术方案 §2 与 `AGENTS.md` §2.1 仍写着
Leaflet —— 两者不一致，且高德那次切换的 ADR 一直没有补签。

维护者决定改为：**Leaflet 负责渲染，高德负责数据**。

## 2. 决策

| 层       | 选型                       | 说明                                        |
| -------- | -------------------------- | ------------------------------------------- |
| 地图渲染 | **Leaflet**                | 容器、瓦片、marker、事件、视口              |
| 底图瓦片 | **OpenStreetMap 标准瓦片** | WGS-84                                      |
| 数据能力 | **高德 JS API 2.0**        | 地理编码 / POI 检索等**数据查询**，不做渲染 |

高德脚本按需加载：只在配置了 Key 且确实要查数据时才注入；缺 Key 时地图与列表
照常工作，只是地址检索不可用。

## 3. 坐标系：这是本决策最大的收益

底图换成 WGS-84 瓦片后，**渲染路径上的坐标转换整个消失了**：

```text
改造前：DB(WGS-84) ──wgs84ToGcj02──▶ 高德渲染   视口 ──gcj02ToWgs84──▶ bbox 查询
改造后：DB(WGS-84) ─────────────────▶ Leaflet   视口 ──────────────▶ bbox 查询
```

原先那句「漏掉转换不会报错，只会让点位静默偏 300 米」的警告，在新栈下**不再适用**：
数据库存的 WGS-84 可以直接喂给 Leaflet，少一层转换就少一个静默偏移源。

仍然需要的只有**一个方向**：高德地理编码返回 **GCJ-02**，写回业务层前必须
`gcj02ToWgs84` 转成 WGS-84。反方向（WGS-84 → GCJ-02）在新栈下没有调用方。

> ⚠️ Leaflet 的坐标顺序是 `[lat, lng]`，与高德的 `[lng, lat]` 相反。
> 本项目对外（API、bbox、数据库）统一用 `lon`/`lat`，
> 传给 Leaflet 时必须写成 `[lat, lon]`。这是本栈最容易出错的地方。

## 4. 能力对照：不要平移旧 Provider 的实现

换栈时最容易犯的错，是把旧实现的容错设计原样搬过来。本次实际**能力变强了**：

| 能力         | 高德（改造前）           | Leaflet（改造后）                |
| ------------ | ------------------------ | -------------------------------- |
| 瓦片失败事件 | **无**（只能靠超时兜底） | `tileerror` / `load`，可精确判定 |
| 底图就绪信号 | `complete`               | `load`                           |
| marker 图标  | 会被剥掉 `<svg>`（实测） | `divIcon` + 自绘 CSS，无此问题   |

因此底图失败检测从「超时兜底」改为**逐瓦片计数**，不再需要
`BASEMAP_LOAD_DEADLINE_MS` 那种猜时间的做法。

## 5. 后果与限制

1. **底图许可变更为 OSM Tile 使用政策**。OSM 标准瓦片面向轻量使用，禁止批量抓取与
   商用重负载。本项目是个人/非商业的文化站，流量量级下合规；**若日后流量显著上升，
   必须换成自建瓦片或商业瓦片供应商**（如需换回高德渲染，走新的 ADR）。
2. **视觉风格变化**：OSM 瓦片与高德矢量底图观感不同，页面需要相应调整配色。
3. **地址检索依赖高德 Key**。未配置时地图与列表正常，只是没有「输入地址查地点」。
4. **CSP**：Leaflet 自身不需要 `unsafe-eval`；但高德插件加载器仍需要（见
   `apps/web/src/security-headers.ts`）。两栈并存时 CSP 仍须保留该指令。
5. 技术方案 §2 的「地图 = Leaflet」一行因此恢复成立；高德不再是渲染层。

## 6. 不受本决策影响的约束

- 坐标可信度规则不变（`AGENTS.md` §3.5）：未核实坐标不画精确点，精度不足只给区域说明。
- 底图失败必须降级、不得阻断列表访问（技术方案 §9.2）。
- 瓦片与归属信息必须显示（OSM 与高德都有署名要求）。
- 首屏列表优先、地图块延迟加载（技术方案 §9.2）。

## 7. 验证方式

```bash
pnpm --filter @nanking-atlas/web build   # 必须能干净构建
pnpm test                                # 含地图纯函数用例
pnpm test:e2e                            # 含 /map 页真实浏览器用例
```

底图渲染、marker 位置、归属信息这类**只有真实浏览器能确认**的行为，
必须用真实浏览器实测，不能只靠单测推断。
